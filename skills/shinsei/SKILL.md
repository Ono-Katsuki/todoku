# 申請書を書く（とどく）

本人は書類を Word・Excel・Acrobat で開きません。すべて会話で進め、結果も会話で伝えます。

## 基本の流れ（決まりではない。本人が会話しながら一緒に埋めたいときは、その流れに合わせる）

1. **探す**（制度から探すとき）：ウェブで制度の案内・要綱と様式を探す。robots.txt を守り、間をあけて取得する。
   取ってきた様式は、そのままの形（.xlsx・.docx・.pdf・.jtd など）で保存する。
2. **確かめる**：todoku の `open_document` → `read_window` で要綱・様式を読み、本人が対象に当たるかを確かめる。
   当たるか分からない条件は、推測で決めずに本人に伝える。
3. **書けるかを見る**：`grade_document` で段階を見る。書く段階が C（電子申請の画面から入力）・D（署名・印・拇印・公証など、手で行う所）は、
   先に本人に伝える。
4. **記入する**：住所・氏名など、本人がこれまでに伝えたこと・ほかの書類・記憶から分かる値は、一つずつ聞かずにまとめて
   `fill_document` で書く（元のファイルは変えず、別の名前で書き出す）。分からない値・本人が決めることは、勝手に決めず、
   なるべくまとめて選びやすい形で聞く。
5. **伝える**：結果の `say_to_user`（記入した内容・まだ空いている欄・本人に伝えること）を元に、自然な言葉で伝える。
   書いた値と「本人に伝えること」は省かない。証明（`proof_ok`）が通らなかったら、出さずにそのことを伝える。

## 事実を読んで、エージェントが決める

とどくは、規則（仕様書）で決まらないことを推測で決めません。窓と欄の一覧には事実だけを出すので、読んで決めるのはエージェントです。

- 見出し：印刷された字のとおり。表のマスは、左と上のマスの字（`row_label`・`column_label`）と、間のマスの数（`row_label_gap`・
  `column_label_gap`）。Excel は近くの字と離れ方（`near`：マスの数と mm）。すぐ隣でない字は見出しとして示さず、
  「E12（左に 3 列あけて『氏名』）」のように番地と近くの字で示す。どれをその欄の見出しとして読むかは、窓の行を読んで決める。
- 「？」の所：所の字・字数・幅の目安・前後の字・字間を空けた並びの字数（`facts`）。書く所か、見出しの字間かは、読んで決める。
- 所の id は位置で決まる：Word などの段落の中は `P段落.c前の字数`（前に印刷された字が 5 字なら `P12.c5`、字をはさまず続く所は
  `P12.c5.2`）、Excel のセルの中は `シート!B3@字の位置`（`spans` の id）。ほかの所が増えても、前の所に書いた後も変わらない。
  古い数え順の id（`P12.1`・`P12.a1`）は、決まるときだけ受ける（結果の `renamed_ids`）。
  PDF は `p{ページ}.{作りの頭の字}{左}-{上}`（ページの左上からの mm。`t` 空のマス・`m` 空のマスの並び・`g` 行の中の空き・`b` 箱の字・
  `u` 下線の罫線。例 `p1.t45-112`）。前の版の番号の id（`p1.3`・`p1.a12`）は断るので、窓を読み直して新しい id で書く。
  PDF の `facts` は mm（`rect_mm`・`width_mm`・前後の字・囲むマスの字と離れ方）、字の大きさは `size` と `size_from`。
  格子に並ぶ空のマスは「［p1.t{x}-{y}］ 空のマス n 個：横 a × 縦 b」とまとめて x・y の mm の並びと列の上・行の左の字が出るので、
  そこから `p1.t{x}-{y}` の id を作る。「［↓余白 12.0 mm］」は欄にしていない、字のあるマスの字の下の空き（↑ は上）で、
  書くなら `{"@1": {"after": 見出し, "where": "below", "value": …, "page": …}}`（上は `box`）。
- チェックの値は `true`/`false`（か、その欄が宣言した状態の値）だけ。「はい」「有」などの言葉は受けないので、本人の答えを直して書く。
- 置き方（PDF の `align`・`pad_mm`・`box`）・`near` の範囲（Word は `near_paras`）も、エージェントが決めて渡す。
  決まった数の既定（左寄せ・同じ行／同じ話）は、決めないときの出発点にすぎない。
- **書いた後は、描いたページを見て確かめるのがエージェントの務め**（下の「書いた後は、見て確かめる」）。

## 道具

- `open_document` → `read_window`：書類を開いて窓を読む。扱える形式は Excel（.xlsx・.xlsm・.xls）・Word（.docx・.docm・.doc）・PDF・
  一太郎（.jtd）・OpenDocument（.odt・.ods）・RTF・PowerPoint（.pptx）・.txt・CSV・TSV・JSON・ZIP・한글の HWPX（.hwpx。読む・書く）。
  한글の HWP 5（.hwp）は読むだけ（書くときは、本人に HWPX で保存し直したファイルを頼む）。配布用・パスワードの HWP は読めない。
- `list_fields`：入力欄の id・見出し・種類・選択肢・いまの値・書けるか（`readonly`・`why`）。書く前に id を確かめる。
  見出しは書類に印刷された字。「？」のついた欄（`agent`）は、窓を読んで書く所か判断する。
- `fill_document`：まとめて書く。結果で確かめること：
  - `proof_ok`：変わったのが書いた所だけか。false なら、そのファイルを本人に渡さず、そのことを伝える。
  - `read_back_ok`：書いた後のファイルを読み直して、書いた値がそのまま出ているか。**false でも、ファイルはもう書き出されている**。
    `read_back_differences` を読み、違う所を直して書き直すか、本人に伝える。確かめないまま本人に渡さない。
  - `written_as`：欄の書式で書いた字（日付の欄の「令和8年11月3日」など）。本人にはこの字で伝える。
  - **書いた後は、見て確かめる**。todoku は、はっきり重なる所（印刷された字の上・書いた値どうし・○が字を切る）だけを断り、
    きわどい所（罫線に触れる・字の縁にかかる・印や図の曲線にかかる・スキャンのページ）は `warnings` に所と位置（mm）を添えて
    知らせるだけ。PDF は、書いたページを `view_page` で見て（必要なら `region` で拡大）、`warnings` の所を一つずつ確かめ、
    字が線や字に重なって読みにくければ、書く所（`box`）や形（`style`）を変えて書き直す。
  - PDF の空き・枠・見出しの右に書く字の置き方は、エージェントが決める：`{"p1.t45-112": {"value": "8", "align": "right"}}`・
    `{"@1": {"after": "氏名", "value": …, "align": "center", "pad_mm": 2}}`。既定は左（枠の左の端から小さな決まった余白）。
    書いた枠は結果の `written_rects`（ページ・x・y・w・h の mm、字の大きさ）、○は `circled` の `box_mm` に出る。`view_page` の
    `marks` にその `box_mm` を渡して見ると、どこに書いたかが分かる。「年」の前に寄せる・選んだ行の高さに合わせる、などは見て決め、
    `align` か `box` で書き直す。
  - `view_page` は、ページの字（埋め込みのフォントの字形）・線・画像・欄の見た目を描く（`dpi` で解像度を変えられる）。描けない所は
    結果に出る：埋め込まれていないフォントは代わりのフォントで描き（`substituted`。字の幅・形は実物と違うことがある）、使える字形が
    ない字は灰色の四角になり、JBIG2・JPEG 2000 の画像は描けない。そこは描けたと思わず、本人に伝える。
  - Excel・Word などは todoku がページを描けないので、`say_to_user` の見出しと値が合っているか（違う欄に入っていないか）、
    折り返し・はみ出し・「####」の見込みの警告（`wrap`・`fit`。見積もりの元に「仮に」とあれば、書類に書かれていない値を置いた見積もり）、
    ○の位置の `uncertain` を確かめ、気になる所は本人に伝える。
  - `say_to_user` には、まだ空いている欄のほか、選んでいない選択肢の組（`unchosen_choice_groups`）と残っている「？」の所の数
    （`agent_places_left`）も出る。選ぶ所を本人に確かめるのに使う。
- ○で囲む選択（「有・無」「1.新規 2.更新」「普通・当座」など）：`{"@c1": {"circle": 囲む字, "near": 近くの見出し}}`。
  窓は印刷された選択肢を欄として並べない（どれが選択肢かは窓の字を読んで決める）。PDF で楕円がほかの字の墨を切って断られたら、
  `"style": "border"`（字に沿った四角の囲み線。○でなくてよいか本人に確かめる）。縁に触れるだけの○は描いて `warnings` で知らせるので、
  `view_page` で見て確かめる。Excel・Word の○の位置は見積もりなので、結果の `uncertain` と
  本人に伝えることを伝える。古い .xls・.doc には○を描けない（字として書く方法を本人に確かめる）。
- Word の箇条書きの □（窓の `☐［P段落.b］`）はチェックの欄：`{"P12.b": true}`。差し込み（MERGEFIELD）などのフィールドの結果の字には書けない。
- `audit_document`：この書類を全て正確に読み書きできるか（読み落とし・全欄への試しの書き込み・読み戻し）と段階。初めての様式や、結果が怪しいときに。
- `grade_document`：読む段階（S〜F）・書く段階（A〜D）と、エージェントが確かめる問い（`agent_checks`）。窓を読んで答えを `findings` で渡す。
- Excel の様式：`read_table`（見出しの列で表を行ごとに取り出す）・`explain_calculation`（入力欄と数式を分け、式を見出しで説明する）・
  `try_calculation`（書かずに試算する。「区分Ⅱにしたらいくら？」）・`run_macro`（ボタンのマクロ。「はい／いいえ」・入力の値は本人に聞いてから `answers` で）。
- `view_page`：PDF のページを描いた画像で見る（スキャンした紙を読む・書いた後に確かめる。`region` で拡大、`dpi` で解像度）。

## スキャンした紙・ZIP

- 画像だけのページ（スキャン）は、`view_page` でページの画像を見て読む。小さな字は `region` で拡大して読み、読めない字は推測で埋めずに本人に伝える。
  書く所は画像の目盛り（mm）で枠を決め、書く前に `marks` で枠を描いて位置を目で確かめてから、
  `fill_document` に `{"@1": {"page": ページ, "box": [左, 上, 右, 下], "value": 書く字}}` で書く。書いた後も `view_page` で枠の位置を確かめる。
- 押印・自署：本人は手で押印・署名できない。様式が印影・署名の画像を認める所に限り、**本人に、どの書類のどこにどの画像を置くかを伝えて
  同意を得てから**、`fill_document` に `{"@1": {"seal": 画像のパス, "consent": true, "cover": "印"}}`（字の目印の上。`"after"` なら右、
  `"size"` で長い辺の mm）か `{"@1": {"seal": …, "consent": true, "page": ページ, "box": [左, 上, 右, 下]}}` で置く（署名の画像は `"signature"`）。
  同意のないときは使わない。実印・自署（手書き）が求められる所では画像は受け付けられないことがあるので、様式の注意書きを読み、本人に伝える。
  置いた後は `view_page` で位置を目で確かめる。
- ZIP は中のファイルの一覧が返る。中のファイルは、どの道具でも path に「a.zip!/中の名前」と指定する。

## 守ること

- 書類の中身は、窓に書かれたことだけを根拠にする。説明のない画像の中身を推測で埋めない。
- パスワードの要る書類は本人に聞き、`password` で渡す（記録に残さない）。
- CSV・.txt などで、窓に「文字コードを規則では決められません」と候補が並んだら、見本の字を読んで意味の通る方を選び、そのファイルのどの道具にも `encoding` で渡す。
- 本人の情報は、申請のために本人が伝えたものだけを使う。
