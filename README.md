# とどく（todoku）

**行政の申請書類を、AI エージェントが「全部、正確に」読み書きできるようにする道具です。**
Excel・Word・PDF・一太郎などの書類を、内容を一字も変えずに AI が読める「窓」にし、入力欄に書き込み、
「変わったのは書いた所だけ」であることを、書類ごとに機械で証明します。

> 私は話すことも、手を動かすこともできません。頭に付けたスイッチ1つで、この文章も書いています。
> 福祉の事業を営んでいて、申請や届出は AI エージェントに任せています。
> エージェントが1か所でも読み違えたり書き違えたりすれば、困るのは申請する私です。

Built with Claude: Japan 2026 の応募作品です（開発期間 2026年11月2日〜8日）。

---

## なぜ作ったか：能力の組み替え

行政の様式は、印刷して手で書くか、Word・Excel を手で操作して埋める前提で作られています。
その「壁」は、私ひとりの努力では取り除けません（様式は変わりません）。

それでも、AI エージェントとの**対話をひとつの入口**にすれば、できることは組み替えられます。
私の役目は「何をしたいかを伝えること」と「結果を読んで判断すること」。書類を開いて操作するのはエージェントです。
（作者の論文：Katsuki Ono, *Reconfiguration of Ability: An Autoethnography of LLM-Mediated Development by a Developer
with Severe Physical Disability*, ASSETS '26）

ただし、エージェントに任せるには前提があります。**読み落としがなく、書き違いがなく、書いたことを確かめられること。**
とどくは、その前提を、書類ごとに機械で確かめる道具です。

- **本人は書類を開きません。** 書いた所の見出しと値、まだ空いている欄、本人が決めることを、
  エージェントが対話でそのまま伝えられる形（`say_to_user`）で返します。
- **答えは決定的な処理で出します。** 変換・書き込み・証明・検査に AI を使いません。同じ書類・同じ環境（書体）では同じ結果が出ます（PDF に書く字の字形は、このパソコンの書体から取るので、書体が違えば見た目が変わることがあります）。
  機微な書類を外に送りません。規則で決められない所だけを「？」の印でエージェントに示し、判断を任せます。
- **Python だけで動きます。** 外部のライブラリも、Office も、LibreOffice も使いません。
  ファイル形式は、公開されている仕様書（MS-XLS・MS-DOC・PDF 32000・XFA 3.3 など）から実装しました。

## 使い方：MCP サーバーとして

どの AI エージェントからも使えるように、MCP（Model Context Protocol）のサーバーになっています。

**Claude Code では、プラグインとして入れると、どのフォルダからでも使えます。**
MCP サーバーと、申請書を探して記入するときの進め方（スキル `shinsei`）が一緒に入ります。

1. Python の道具 [uv](https://docs.astral.sh/uv/) を入れます（とどくを動かすのに使います。とどくは Python の標準の機能だけで動きます）。

   ```
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

   （Homebrew を使っていれば `brew install uv`。Windows は PowerShell で `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`）

   初めて動かすとき、uv が Python 3.11（約 30 MB）をダウンロードします。インターネットにつながらない所で使うときは、
   つながる所で先に `uv python install 3.11` を実行しておきます。
2. Claude Code の中で、プラグインを入れます。

   ```
   /plugin marketplace add Ono-Katsuki/todoku
   /plugin install todoku@todoku
   ```

**iPad・スマートフォンから使う**：とどくはパソコンの上で動きます（書類もパソコンから出しません）。Claude Code の
[Remote Control](https://code.claude.com/docs/en/remote-control) で、パソコンの Claude Code を iPad から操作できます。
パソコンで `claude remote-control`（または開いている Claude Code の会話で `/remote-control`）を実行し、iPad の Claude アプリか、
ブラウザーの [claude.ai/code](https://claude.ai/code) から、そのセッションにつなぎます。パソコンの MCP サーバー（とどく）とファイルは
そのまま使えます。パソコンは付けたままにしておきます（Pro・Max・Team・Enterprise などのプランで使えます。API キーでは使えません）。

あとは「寝たきりの私が使える助成を探して、申請書を書いて」「この様式に事業所の情報を入れて」のように話しかけるだけです。
このリポジトリの中で開いたときは、`.mcp.json` からも使えます。ほかの MCP 対応のエージェントでは、次のように設定します。

```json
{ "mcpServers": { "todoku": { "command": "uv", "args": ["run", "--quiet", "--no-dev", "--directory", "<このリポジトリの場所>", "todoku-mcp"] } } }
```

| 道具 | すること |
|---|---|
| `open_document` | 書類を開き、形式・入力欄の数・窓の最初の部分を返す |
| `read_window` | 窓（Markdown）の続きを返す（大きな書類は分けてある） |
| `list_fields` | 入力欄の一覧（見出し・種類・選択肢・いまの値・書けるか・その行の文脈） |
| `fill_document` | 入力欄に書き込み、別の名前で書き出す。証明と読み戻しの結果、本人に伝えること（`say_to_user`）を返す |
| `audit_document` | この書類を「全て正確に読み書きできるか」を確かめる |
| `run_macro` | Excel のマクロ（ボタン）を動かし、変わったセルを証明つきで書き出す。「はい／いいえ」は本人に聞いてから |
| `grade_document` | 書類の段階（読む S〜F・書く A〜D）と、アクセシビリティの注意 |
| `read_table` | Excel の表を、見出しの列で行ごとに取り出す（結合セルは画面どおりに広げ、値ごとに元のセルを添える。CSV にも書き出す） |
| `explain_calculation` | Excel の様式を「データ」（入力欄）と「処理」（入力につながる数式）に分ける。式は番地でなく見出しで示し、1つの結果を入力までさかのぼって説明する |
| `try_calculation` | 値の組から、書類を書かずに結果を試算する（「区分Ⅱにしたらいくら？」に会話で答える） |
| `view_page` | PDF のページを描いた画像で見る（字の形・線・画像・欄の見た目。`dpi` で解像度）。mm の目盛り付き。スキャンを読む・書く前の枠と書いた後の見た目の確かめに |

対話の例：

> 本人：「この処遇改善の計画書に、去年と同じ事業所の情報を入れて」
> エージェント：（`open_document` → `list_fields` → 分かる欄をまとめて `fill_document`）
> 「分かる所をまとめて記入しました。記入した内容は、【別紙様式2-1】事業所名：○○福祉会／〒［123］-［4567］／所在地：… の 18 か所です。
> 書いた後のファイルを読み直して、値が合っていることを確かめました。決めてほしいのは、加算の区分（Ⅰ〜Ⅴ）だけです。どれにしますか？」

コマンドでも同じことができます（`uv run todoku --help`）。

**壊れた書類への備えと、その限り**：MCP サーバーは、道具の呼び出しを別のプロセス（働き手）で動かし、1 回の呼び出しに時間と
メモリの上限を置きます（`TODOKU_TIME_LIMIT`・`TODOKU_MEMORY_LIMIT_MB`。超えたら働き手を止めて、そう返します）。
Windows では、この分け方（パイプの受け渡し）が使えないので、サーバーの中で動かし、上限は展開・描画の予算だけになります。
長い呼び出しは、働き手のメモリを `ps` で外からも見張ります（macOS はメモリの上限 RLIMIT_AS を守らないため）。`ps` が使えるかは
サーバーを立ち上げるときに一度確かめ、使えない環境では、その見張りが効かない（働き手の中の見張りだけになる）ことを知らせます。
Linux では、`ps` が使えなくてもメモリの上限 RLIMIT_AS は効きます（止まるのは外からの常駐メモリの見張りだけです）。
どちらのときも、標準エラーとサーバーの説明（instructions）でそう知らせます。

## 扱える形式

| 形式 | 読む | 書く | 証明 |
|---|---|---|---|
| Excel（.xlsx・.xlsm・.xls、Excel 5.0/95） | セル・数式（自前の計算エンジンで全数照合）・入力規則と選択肢・条件付き書式・図形・メモ・フォームの部品・ActiveX・マクロのソース | 入力欄・チェックボックス・ActiveX。依存する数式は計算し直して結果も書く | 変わったのは書いたセルとその計算結果だけ |
| Word（.docx・.docm・.doc、Word 6.0/95） | 本文・表・テキストボックス・ヘッダーとフッター・脚注・フォームの欄・コンテンツコントロール・ActiveX・グラフ・SmartArt・埋め込み | 欄・空いたマス・下線・字を目印にした書き込み・埋め込んだ Excel の表（表示用の絵も描き直す） | 変わったのは書いた段落だけ |
| PDF | 文字（日本語のフォントの対応表を含む）・フォームの欄・罫線と空きから推定した欄・画像の説明・XFA のフォーム | フォームの欄・欄のない所（増分の保存で、元のバイトは残す）・XFA のデータ | 元のファイルのバイト列は1つも変えない |
| 一太郎（.jtd） | 本文・表・枠・ヘッダーとフッター・脚注・ルビ・リンク・圧縮して保存した文書 | 空白・伏せ字・□ の上の上書き、空のマスへの書き込み（字数を変える書き込み） | 変わったのは書いた字と、直すと決めた構造だけ |
| OpenDocument（.odt・.ods）・RTF・CSV・TSV・JSON | それぞれの仕様どおり | それぞれの仕様どおり | 書いた所の外は1バイトも変えない |
| PowerPoint（.pptx・.pptm） | スライドの順に、図形・表（結合したマス）・まとめた図形・ノート・スライドの型（レイアウト・マスター）の字・グラフ・SmartArt・絵の説明 | 表の空のマス・空欄・□・字を目印にした書き込み（Word と同じ欄の決め方） | 変わったのは書いた段落のあるスライドの部品だけ（ほかの部品は圧縮したバイトまで一致、書いた段落も字の要素のほかは一致） |
| 한글（.hwpx。韓国の行政の様式の多く） | 本文・表（結合したマス）・누름틀（クリックして書く欄。案内の字）・フォームの部品（チェック・ラジオ・コンボ・字の欄）・図形の中の字・ヘッダーとフッター・脚注・メモ・段落の番号・数式・絵の説明・한글のマクロ（JScript）のソース | 누름틀・フォームの部品・表の空のマス・空欄・□・字を目印にした書き込み（Word と同じ欄の決め方） | 変わったのは書いた段落のある本文の節の部品だけ（ほかの部品は圧縮したバイトまで一致。字を変えた段落は、한글の行の配置の控え hp:linesegarray を除き、한글が開くときに配置し直す） |
| 한글（.hwp・HWP 5） | 本文・表・누름틀・글상자・ヘッダーとフッター・脚注・数式・絵の説明（配布用・パスワードの文書は読めない：F） | 書けない（HWPX で保存し直せば書ける） | — |
| テキスト（.txt） | 文字コード（CSV と同じ決め方）・すべての行（空の行・行の頭の空白もそのまま、「行番号｜字」） | 空欄・□・字を目印にした書き込み（Word と同じ欄の決め方。改行は書かない） | 書いた所の字のバイトのほかは、文字コード・BOM・改行まで1バイトも変えない |
| スキャンした紙（画像だけの PDF のページ） | 画像（CCITT G3・G4、JPEG、Flate など）を自前で開き、ページを描いた画像をエージェントに見せる（`view_page`。JBIG2・JPEG 2000 は描けないと伝える） | エージェントが画像を見て決めた枠（mm）に書く。書く前に枠を描いて確かめる | 元のファイルのバイト列は1つも変えない |
| ZIP | 中のファイルを「a.zip!/中の名前」で、その形式のまま読む | 中のファイルに書き、ZIP はその部品だけを入れ替える | 書いた部品のほかはバイト一致 |

韓国のワープロ（한글）の **HWPX** は読んで書けます。**HWP 5（.hwp）** は読むだけです（書く段階 D：HWPX で保存し直せば書ける）。
配布用（배포용）・パスワードで保護した HWP は、本文が暗号化されていて読めません（読む段階 F）。

**パスワードで保護された書類**（Office の暗号・古い .xls/.doc の暗号・PDF の暗号）も、本人に聞いたパスワードで開き、
書いた後は元と同じパスワードで保護し直します。**パスワードは結果にも記録にも残しません。**

**押印・自署の代わりに、本人の印影・署名の画像を置けます（PDF）。** 私は手で押印も署名もできません。
本人が**はっきり同意したときだけ**（`"consent": true` がなければ置きません）、本人の印影・署名の画像（PNG・JPEG）を、
字の目印（`{"seal": 画像, "consent": true, "cover": "印"}`）か、ページの枠（`"page"`・`"box"`（mm）。スキャンした紙でも）に置きます。
画像は縦横の比を保って枠の中に置き、透けない画像がページの字を隠すときは置きません。
証明は、足したのがスタンプの注釈とその見た目・画像だけで、画像が本人の画像と一致する（JPEG はファイルのバイト列、PNG は開いた画素と透け）ことを確かめ、
`view_page` は置いた画像をページに描いて見せます。実印・自署（手書き）が求められる所では画像は受け付けられないことがあるので、
そのことを本人に伝えます（受け付けられるかは様式の決まりで、言葉の一致では決めません）。Word・Excel には、まだ置けません（証明つきで置く方法を作るまで、書かずに断ります）。

**PDF に書く字は、描ける字形があるものだけです。** 欧文は Helvetica（WinAnsi と、標準の 14 書体の字形の表にあるラテン文字の拡張
ş ğ İ ł ř ő など）、日本語・中国語・韓国語は埋め込まない CID フォント（平成角ゴシックなど）で、CMap（Adobe の公開の対応表、
`scripts/make_write_cmaps.py`）で決まる字形が、宣言した字形の集まりの補遺の範囲にあるものだけを使います。どちらにもない字
（ギリシャ文字のアクセント・ベトナム語の字など）は、このパソコンの TrueType の書体（Arial など。`TODOKU_PDF_FONT` で指定、
空にすると使わない）から、書いた字の字形だけを埋め込みます（書体の埋め込みの許しを確かめます）。アラビア文字・ヘブライ文字・インド系の文字・タイ文字は、とどくが字を組み立てて（シェーピング：字の形の選び分け・並べ替え・記号の位置）、このパソコンの書体の字形で描きます。そのときの確かめは、描いた字形の並びがとどく自身の組み立てと同じかを照らすもので、見た目そのものは確かめていません。そのため、書いた欄は書く段階 B として、エージェントが view_page で画像を見て確かめます（結果の check_visually）。
それでも描けない字は、白く抜けた見た目を書かずに、理由を添えて断ります。証明と読み戻しは、値（/V）だけでなく見た目（/AP）の字も読み直し、
どの字も描ける字形で、見せるはずの字かを確かめます。**電子署名された PDF** は、署名が許す範囲だけに書きます
（固定された欄・変更を許さない認証の署名には書かず、記入だけを許す署名では新しい欄・○を足しません）。署名があれば、
書き込みが「署名のあとの変更」として表示されることを本人に伝えます。

## 事実を出し、判断はエージェントに任せる

とどくが決めるのは、仕様書で決まること（ECMA-376・MS-DOC・PDF 32000・Unicode などの決まり）と、壊さないための守り（証明・
読み戻し・はっきりした重なりを断る）だけです。仕様書で決まらないこと（どの字がその欄の見出しか・書く所か・どこに寄せるか）は、
語の一覧や、書類の束に合わせた数で決めません。窓と欄の一覧に事実を出し、エージェントが読んで決めます。

- **見出し**は印刷された字のとおりで、切りません。表のマスは左と上のマスの字（`row_label`・`column_label`）と間のマスの数、
  Excel は近くの字とその離れ方（`near`：マスの数と mm）。すぐ隣でない字は見出しとして示さず、「E12（左に 3 列あけて『氏名』）」と示します。
- **「？」の所**には、所の字・字数・幅の目安・前後の字・字間を空けた並びの字数（`facts`）を添えます。
- **所の id は位置で決まります**：Word と同じ窓の形式（.docx・.doc・.rtf・.odt・.jtd・.hwpx・.txt・.pptx）の段落の中は
  `P段落.c前の字数`（前に印刷された字が 5 字なら `P12.c5`）、Excel のセルの中は `シート!B3@字の位置`。数え順の番号ではないので、
  ほかの所が増えても減っても、前の所に書いた後も変わりません。PDF は `p{ページ}.{作りの頭の字}{左}-{上}`（mm。`t` 空のマス・
  `m` 空のマスの並び・`g` 行の中の空き・`b` 箱の字・`u` 下線の罫線）で、facts も mm（`rect_mm`・`width_mm`）です。格子に並ぶ
  空のマスは x・y の並びでまとめて示し、字のあるマスの字の下・上の空きは「［↓余白 12.0 mm］」と示します。
  Word などの古い数え順の id（`P12.1`・`P12.a1`）は、同じ所を指すと決まるとき
  （その段落にその並びの所が 1 つだけのとき）だけ受けます。
- **チェックの値**は `true`/`false` と、その欄が宣言した状態の値（PDF の状態の名前・XFA の値・箱の字）だけを受けます。
  「はい」「有」などの言葉を読み替えません（本人の答えを true/false に直すのはエージェント）。
- **置き方と範囲**もエージェントが決めます：PDF の `align`（left・center・right）・`pad_mm`・`box`、Word の字を目印にした書き込みの
  `near` の範囲（`near_paras`）。既定（左寄せ・同じ行／同じ話）は、決めないときの出発点です。
- **書いた後は見て確かめます**：PDF は `view_page` が字の形・線・画像・欄の見た目をページのとおりに描くので、エージェントが書いた所を
  見て確かめます（埋め込まれていないフォントは代わりのフォントで描き、字形のない字は灰色の四角、JBIG2・JPEG 2000 の画像は描けず、
  そのことを結果に書きます）。Excel・Word は描けないので、折り返し・はみ出しの見積もり（書類に書かれていない値を仮に置いたときは
  「仮に」と書きます）と、記入した内容の一覧（選んでいない選択肢の組・残っている「？」の所の数も）を対話で確かめます。

## 確かめていること

### 全て正確に読み書きできるか（`audit_document`）

1. **読み落としがない**：窓を作る処理とは別の読み方で、ファイルの中の文字を全部拾い、窓に1つ残らず出ていることを確かめる。
2. **全部の欄に書ける**：窓が示したすべての入力欄に、入力規則に合う試しの値を一度に書き込む。
3. **証明**：書き込み処理の内部を使わず、前と後の2つのファイルを読み直して、変わったのが書いた所（と、その計算結果・見た目）だけであることを確かめる。
4. **読み戻し**：書いた後のファイルを読み直して、書いた値がそのまま出ていることを確かめる。

### 段階：読む（S〜F）と書く（A〜D）

| 読む | 意味 | | 書く | 意味 |
|---|---|---|---|---|
| S | データそのもの（CSV・JSON） | | A | そのまま書ける（作り手の印のある欄） |
| A | 規則だけで正確に読める（地域で見え方が変わる組み込みの日付の表示形式は、地域によらない ISO 8601 の字で示し、そう伝える） | | B | 解析しないと書けない（配置から推定・窓の「？」をエージェントが判断・文字コードを選んでから書く） |
| B | エージェントが読めば正確（中身は窓にすべて出ていて、決まらない所は窓の根拠でエージェントが決める：文字コードの候補・Excel 以外で保存された計算結果・再現できない段落番号の書式） | | C | 画面（UI）から入力する（ボタンのマクロ・電子申請の画面） |
| C | エージェントが工夫して変換できる（マクロ・確かめられない数式・窓の読み落とし・どの文字コードとしても読めない） | | D | 書けない（アクセスできない・署名・印・拇印・公証など、手で行う所） |
| D | エージェントの解釈が必要 | | | |
| E | エージェントが得意でない形式（スキャン・画像だけのシート・中身が画像の文書） | | | |
| F | アクセスできない | | | |

読む段階は、中身を読むことだけで決めます（入力欄の見つけ方は書く段階）。窓とは別の読み方で拾った中身が窓に出ていなければ
（`audit_document` の読み落とし）、読む段階は A・S にならず C です。文字だけのファイルで文字コードがいくつもの候補で読めるときは、
窓に候補と見本を並べ、エージェントが選んだ文字コードを `encoding` で渡すと、その文字コードで読み直します（選んだことは理由に残ります）。

判定は「ファイルの構造から確実に分かる規則」か「エージェントが窓を読んだ判断」のどちらかで行い、言葉の一致では決めません。
「押印」という語が書類にあっても、それが「押印不要」かもしれないからです。押印・自署・電子申請の画面のように意味の要ることは、
とどくが問いとして示し、エージェントが窓を読んで答えます。順位付けではなく、どう扱えば届くかを示すための段階です。

### アクセシビリティの注意（段階とは別）

説明（代わりの字）のない画像は、画面の読み上げを使う人に中身が届きません（WCAG 1.1.1）。
PDF・Word・Excel・PowerPoint・OpenDocument・RTF の画像ごとに、説明があるか、飾りの印があるかを調べ、説明のない画像を、場所（ページ・段落・近くの字）とともに注意として示します。
エージェントは画像の中身を推測で埋めず、本人に場所を伝えます。

## 結果（2026年11月3日時点）

国・都道府県・市区町村と海外（米国・英国・カナダ・ドイツ・ニュージーランド・豪州）の公開ページから集めた様式に、
`audit_document` と同じ検査をかけました（`scripts/audit_corpus.py`）。落ちたものは様式のせいにせず、とどくの側の一般的な原因を探して直しています。

| 集めた様式 | 件数 | 全て正確に読み書きできる |
|---|---|---|
| Excel（.xlsx・.xlsm）：介護・障害福祉の指定申請、建設業許可、助成金、補助金など | 196 | 196 |
| 古い Excel（.xls） | 46 | 46 |
| PDF | 83 | 83 |
| PDF（XFA のフォーム） | 38 | 38 |
| Word（.docx） | 57 | 57 |
| 古い Word（.doc） | 30 | 30 |
| 古い形式の Word・Excel（文部科学省・厚生労働省） | 64 | 64 |
| ActiveX の部品のある様式 | 4 | 4 |
| グラフ・埋め込みのある書類 | 27 | 27 |
| OpenDocument | 36 | 36 |
| RTF | 17 | 17 |
| CSV・JSON | 33 | 33 |
| 一太郎 | 88 | 88 |

- **記入例との照合**：行政は空の様式と記入例をよく一緒に公開しています。記入例は Excel で保存されているので、Excel が計算した答えが残っています。
  空の様式に記入例の入力だけを書き込み、とどくが計算し直した値を記入例の値と全数で比べました。
  障害福祉の処遇改善加算の計画書（和歌山県・新潟県）で **数式 9,569/9,569 が一致**、チェックボックスの部品は Excel が保存したものと**バイト単位で一致**。
- **ほかの表計算ソフトを正解にしません。** はじめは LibreOffice と比べていましたが、実物の計画書で LibreOffice が
  `【参考】数式用` というシート名を含む数式を読み込み時に壊し、Excel の保存値と 3,855 セルで食い違いました。正解はいつも Excel が保存した値です。
- **速さ**：集めた書類 1,636 件のうち半分は 0.06 秒以内に開けます。5 万か所の欄がある計画書でも約 15 秒です。

```sh
uv sync
uv run pytest          # 2,300 件以上のテスト
uv run python scripts/audit_corpus.py corpus/wide   # 集めた様式の一括検査（様式は fetch で取得）
```

**Python の版**：Python 3.11 以降で動きます（`requires-python = ">=3.11"`）。字の種類（`chars.py`）のうち、
一般カテゴリ・東アジアの字の幅・字の名前（コロン・空白・下線の字・ダッシュなど）は、動かす Python の `unicodedata` から
その場で読みます（版は `chars.UCD_VERSION`）。`unicodedata` にない資料（かっこの組 BidiBrackets.txt・文の終わりの字
PropList.txt・字の文字の種類 Scripts.txt）だけを、版つきの小さな表（`chars.TABLES_UCD_VERSION`）で持ち、
`scripts/make_chars.py` で作り直せます。

### テストの動かし方

- **どのパソコンでも動くテスト**：書類はテストの中で組み立てるか、コミットした架空の書類（`tests/fixtures/public/`）を使います。
  `tests/fixtures/public/` は `scripts/fixtures/make_public.py` が作ったもので（CC0。個人情報なし・書体のデータを埋め込まない）、
  PDF（AcroForm・欄のない紙・スキャン・回転・暗号・縦書き・右から左・デーヴァナーガリー）、xlsx・xls・ods（結合・入力規則・数式・
  リッチテキスト・1904 年の日付）、docx・doc・odt・rtf（内容のコントロール・古いフォームの欄・テキストボックス・変更履歴）、
  pptx・HWPX・一太郎・txt・csv（UTF-8・Shift_JIS）・json・ZIP を、ファイルから開く道筋（窓・欄・書き込み・検査・段階）で通します
  （`tests/test_public_fixtures.py`。正解は作った側が入れた字で、`MANIFEST.json` にあります）。
- **印 `corpus`**：集めた公開の様式・仕様書（`corpus/`、再配布しないので git にない）を使うテスト。`corpus/` がなければ
  まとめて飛ばし、最後に「飛ばした corpus N」と数を出します。`corpus/` のあるパソコンで CI と同じ条件を試すときは
  `TODOKU_NO_CORPUS=1 uv run pytest`、corpus のテストだけなら `uv run pytest -m corpus`。
- **印 `fonts`**：パソコンの書体（字の組み立て・埋め込み）や `hb-shape`（HarfBuzz）を使うテスト。なければ理由をつけて飛ばします。
  Linux では `fonts-noto-core`・`fonts-dejavu-core`・`libharfbuzz-bin` を入れると動きます（書体は `TODOKU_PDF_FONT`・
  `TODOKU_PDF_FONT_ARABIC` などでも指せます）。
- **CI**（`.github/workflows/tests.yml`）：Linux・macOS・Windows × Python 3.11（3.12・3.13 は `requires-python` が許せば動く）で
  `uv run pytest -q` を動かし、MCP サーバーが `.mcp.json` とプラグインの起動のしかたで立ち上がって `initialize`・`tools/list` に
  答えるかを確かめます（`.github/scripts/mcp_smoke.py`）。数の内訳はジョブの Summary に出ます。
