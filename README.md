# とどく（todoku）

PDF・Excel・PowerPointを、**内容を一字も変えずに**AIや支援技術から扱える形に変換し、
元のファイルに**バイト単位で戻せる**ことまで保証する道具です。あわせて、書類の作り手が自分で壁に気づける診断を付けます。

> AIが人と世界をつなぐ入口になった今、機械可読性はアクセシビリティそのものである。

Built with Claude: Japan 2026 の応募作品です（開発期間 2026年11月2日〜8日）。

## いまできること（Excel：xlsx / xlsm）

| コマンド | すること |
|---|---|
| `todoku convert 書類.xlsx -o out/` | 読むための窓（JSON・Markdown）、診断（HTML・JSON）、関数の照合結果を作る |
| `todoku verify 書類.xlsx` | 往復のバイト一致と、関数の全数照合 |
| `todoku fill 書類.xlsx --set 'シート!セル=値' -o 記入後.xlsx` | 元の様式に書き込む。変えるのは書き込んだ値と、その計算結果だけ |
| `todoku apply 窓.json --original 書類.xlsx -o 記入後.xlsx` | AIが窓（JSON）の入力欄を書き換えたものを、元のファイルに差分として適用 |
| `todoku diagnose 書類.xlsx --html 診断.html` | 作り手向けの診断（4段階のラダー） |
| `todoku audit 書類.xlsx [--example 記入例.xlsx]` | エージェントが**全て正確に読み書きできるか**を確かめる（読み落とし・全欄への書き込み・読み戻し） |
| `todoku example 空の様式.xlsx 記入例.xlsx` | 記入例（Excelが計算した答え）と照らして、記入と再計算が正しいかを全数で確かめる |
| `todoku bake 書類.xlsx -o 出力.xlsx` | 計算結果が保存されていない数式に、Excelと同じ規則で計算した値を書き込む |

```sh
uv sync
uv run todoku convert tests/fixtures/kami_meisai.xlsx -o out
uv run todoku fill tests/fixtures/kami_meisai.xlsx --set '明細書!O9=20' --set '明細書!I4=1級地' -o out/記入後.xlsx
# → 変更 12 か所（入力 2・計算結果 10）。それ以外は元とバイト一致（ZIPのエントリ 9/10 が完全一致 …）
uv run todoku audit tests/fixtures/kami_meisai.xlsx
# → 読み落とし 0、全入力欄への書き込みと読み戻しが一致 → 「全て正確に読み書きできます」
```

## エージェントが全て正確に読み書きできるか

申請書類は、1か所の読み違いや書き違いが、申請する本人の不利益になります。とどくは「だいたい読める」ではなく、
**全部を正確に**読み書きできることを、書類ごとに機械的に確かめます（`todoku audit`）。

### 読む

- **読み落としがない**：窓を作る処理とは別に、ファイルのXMLを直接読んで、セルの文字と数値・図形の文字・メモ・
  入力規則の説明・ヘッダーとフッターを全部拾い、窓に1つ残らず出ていることを確かめます。
  結合セルの陰に残っている値（Excelの画面には出ない値）も、そうと分かる印を付けて窓に入れます。
- **見えているとおりに伝える**：読み順は、画面に見える行を上から、行の中は左から並べます。非表示の行と列、
  印刷範囲の外、条件付き書式で「いまは見えない」警告文（背景と同じ色にして隠すもの）は、そのとおりに区別します。
  条件付き書式の式は自前の計算エンジンでセルの位置ごとに計算します。
- **同じ言葉を取り違えない見出し**：見出しは配置から決めます（推定なので、判断の材料にした行も添えます）。
  - 「氏名」が2つあっても「法人代表者／氏名」「書類作成担当者／氏名」と区別する（縦に結合された区分、最初の行にだけ書かれた区分も引き継ぐ）
  - 「令和［▶］年［　］月［　］日」のように、日付を分けて書くマスは、どのマスが年・月・日かを示す
  - 郵便番号のように1マスに1文字ずつ書く欄、表の列の見出し（2段まで）、チェック欄の右に書かれた項目文
  - 見出しの文字は変えない（全角・半角、①などの番号もそのまま）
- **選択肢を展開する**：入力規則の一覧（別シートの範囲・名前・INDIRECT）は、そのセルの位置で計算して、選べる値そのものを示します。
  都道府県で市区町村が決まるような連動も、Excelと同じく相対参照をずらして計算します。

### 書く

- **Excelで手入力したときと同じ規則で受け取る**：全角の数字は数値に、「令和8年4月1日」「R8.4.1」は日付の書式のセルなら日付に、
  パーセントの書式のセルへの「8」は 8% に。先頭の0や15桁を超える数字は、Excelのように消さずに文字として残し、そう知らせます。
  セルの書式は変えません（Excelなら書式まで変える入力は、文字のまま書き、そのことを知らせます）。
- **Excelが受け付けない値は受け付けない**：入力規則のエラーが「停止」のもの、シート保護でロックされたセル、数式のセルには書き込みません。
- **チェックボックス**：つながったセルと、チェックボックスの部品（ctrlProp と VML）の両方を書き換えます。
  公開されている記入例と比べると、書き換えた部品は**Excelが保存したものとバイト単位で一致**します。
- **全欄への書き込みと読み戻し**：窓が示したすべての入力欄とチェックボックスに、入力規則に合う試しの値を一度に書き込み、
  変わったのが書いた欄とその計算結果だけであること、構造の検査に通ること、書いた値が窓にそのまま読み戻せることを確かめます。

## 汎用性の検査：特定の様式に合わせ込まない

上の6件だけで正しくても意味がありません。国・都道府県・市区町村と海外の公開ページ48か所から、
申請・届出の様式を集め（`scripts/collect_forms.py`、robots.txt に従い間隔をあけて取得）、
全件に `todoku audit` をかけました（`scripts/audit_corpus.py`）。落ちたものは様式のせいにせず、
とどくの側の**一般的な原因**を探して直しています。

- 集めた様式：195 件（日本 179 件：介護・障害福祉の指定申請、建設業許可、雇用関係助成金、補助金、保育など。
  海外 16 件：米国9・英国4・ニュージーランド2・豪州1。補助金の予算様式など）。取得元は `tests/sources.json`。
  入力欄とチェックボックスは合わせて約13万か所。
- 結果：188/195 件で「全て正確に読み書きできる」。読み落としは全件で0、書いた値の読み戻しは全件で一致。
- 残りは、黙って通さずに「要確認」と表示しているもの：
  - **入力規則の重なり**（2件）：1つのセルに入力規則が2つ定義されている。Excelがどちらを使うかはファイルから決まらないので、推測で止めず警告にとどめ、様式の作り手に直してもらう点として示す。
  - **マクロ**（4件）：ボタンで動くマクロの処理は、まだ再現していない。
  - **動的配列の関数**（1件、英国ウェールズ政府の様式）：SEQUENCE・FILTER は、まだ再現していない。この欄に関わる書き込みでは、Excelで開いたときに計算し直すよう設定し、そのことを表示する。
- 取得を止められたページ（403など）は、破らずに「止められた」と記録しています。

広く集めて見つかった、一般的な原因（すべて直しました）：

| 見つかったこと | 直し方 |
|---|---|
| 「①」を入力すると「1」になっていた（全角を半角にする処理が広すぎた） | 全角の数字・符号だけを半角にする。①や㈱は変えない |
| 入力規則の数式の基準セルを、範囲の書き順で決めていた | 範囲全体の左上を基準にする（「N20 N8:O8」でも N8） |
| 外部ブックへの参照・テーブルの列名での参照が計算できなかった | 外部ブックはリンクに保存された値を使い（Excelが更新しないときと同じ）、テーブルは定義から範囲を求める |
| SUBTOTAL・LET・ADDRESS・CELL・WEEKDAY（種類11〜17）・PHONETIC、`_xlfn.` 付きの新しい関数 | Excelの仕様どおりに実装 |
| TODAY() を使う欄に依存する値を「不一致」と数えていた | 計算のたびに変わる値として区別する |
| 2行で1人分の表、数行おきの欄、5万か所の欄で窓が大きくなりすぎた | くり返しをまとめ、なお大きければ目次と部分に分ける |
| 条件付き書式で隠れた警告を、見えているものとして出していた | 条件付き書式を計算し、いま見えない文字は読み順に出さない |
| 横に並んだ2つの表で、行の見出しを取り違えた | 左へたどって最初の見出しを、その表の行の見出しにする |
| 元のファイルにもある構造の問題を、書き込みのせいにしていた | 書き込みで新しく生じた問題だけを数える |
| 条件にエラー値（#N/A）が入った SUMIFS を、エラーにしていた | Excelと同じく、同じエラー値のセルだけが当てはまる条件として扱う |
| SUMPRODUCT の中の COUNTIFS(範囲, 範囲) を、1つの値として計算していた | 条件の要素ごとに計算して配列で返す |
| 空のセルを VALUE に渡すと #VALUE! にしていた | Excelと同じく 0 にする |
| テーブルの列名の末尾の空白（「Amount Claimed (£) 」）を落としていた | 列名は空白も含めてそのまま照らす |
| 1つのセルだけの結合を、構造の問題と判定していた | Excelが受け付けるものは問題にしない |

### 様式の形式

集めたページに載っていた様式の形式は、PDF 40%、Excel（xlsx）35%、古いExcel（xls）12%、Word 13% でした。
「どんな申請でも」に届くには、Excel（xlsx）だけでは足りません。古いExcel・PDF・Wordにも、同じ保証（一字も変えない往復、
読み落とし0、書いた値の読み戻し）で広げていきます。

## 4段階のラダー

| 段階 | 問い |
|---|---|
| 0. 届く | エージェントが書類にたどり着き、取得できるか |
| 1. 読める | 文字と構造を正しく取り出せるか |
| 2. 操作できる | AIが本人の指示で記入・実行できるか |
| 3. 検証できる | 結果が正しいと確かめられるか |

## 検証の考え方

- **元のファイルが正本**。作り直さない。窓は「読むためのもの」で、書き込みは元のファイルへの差分。
- **往復**：ZIPをローカルヘッダ・圧縮データ・中央ディレクトリのバイト列として保持し、変更のないエントリは圧縮済みのままコピーする（`src/todoku/zipraw.py`）。
- **編集**：シートのXMLを保存し直さず、書き込むセルと、計算結果が変わる数式セルの `<v>` だけをバイト列の上で差し替える（`src/todoku/xlsx/edit.py`）。
- **証明**：書き込み処理の内部情報を使わず、前後の2ファイルを読み直して、変わったのが指示したセルとその計算結果だけであることを確かめる（`src/todoku/xlsx/proof.py`）。
- **関数**：数式を自前の計算エンジンでExcelと同じ規則（有効数字15桁、ROUNDは0から遠い方へ、1900年うるう年バグ、和暦の表示形式など）で計算し直し、Excelが保存した計算結果と全セルで照合する（`src/todoku/formula/`）。
- **記入**：行政は空の様式と記入例を一緒に公開していることが多い。記入例はExcelで保存されているので、Excelが計算した答えが残っている。
  空の様式に記入例の入力値だけを書き込み、こちらで計算し直した値を記入例の値と全数で比べる（`src/todoku/xlsx/example.py`）。
- **互換**：書き出したファイルが、Excelが修復なしに開くための構造の条件（要素の順序、セルの並び、型と値の対応、パッケージの関係）を満たすかを直接検査する（`src/todoku/xlsx/lint.py`）。

**ほかの表計算ソフトは使いません。** 正解はいつも、Excelが保存した値です。
はじめはLibreOfficeでの再計算と比べていましたが、実物の計画書では、LibreOfficeが `【参考】数式用` というシート名を含む数式を読み込み時に壊し、
未記入の状態でもExcelの保存値と 3,855 セルで食い違いました（とどくは 9,569/9,569 一致）。ソフトごとの違いを正解に持ち込まないため、外しました。
動かすのに必要なのは Python だけで、外部のライブラリもOfficeも要りません。

変換・検証・診断はすべて **AIを使わない決定的な処理** です。機微な書類を外部に送らず、費用をかけずに、同じ入力から必ず同じ結果が出ます。
出力のすべての項目に、どうやって得たか（`provenance`）を付けます。

### 合格条件とテスト

```sh
uv run pytest
```

| テスト | 合格条件 |
|---|---|
| 往復 | 変換して戻したファイルのSHA-256が元と一致 |
| 編集 | 元との差分が、入力したセルとそれに依存する数式セルの値だけに収まる |
| 関数 | 全セルで保存済みの計算結果と一致 |
| 記入 | 空の様式に記入例の入力を書き込むと、記入例でExcelが計算した値と全数で一致。チェックボックスの状態と部品も一致 |
| 読み書き | 読み落としが0、全入力欄に書き込めて、書いた値がそのまま読み戻せる（`todoku audit`） |
| 互換 | 書き出したファイルが、Excelが修復なしに開くための構造の条件を満たす（Excelで保存された41ファイルで誤検出 0） |

## 書類の出どころ

テストと検証に使った書類の取得元です。書類そのものはリポジトリに含めません（`corpus/` は `.gitignore`）。
取得元のURLとSHA-256は `tests/forms.json` に記録してあり、`uv run python scripts/fetch_forms.py` で同じものを取得できます
（様式が差し替えられていれば、そう表示します）。

| 書類 | 取得元 |
|---|---|
| 令和8年度 福祉・介護職員等処遇改善加算 計画書（別紙様式2）・記入例・変更届出書（別紙様式4）・特別な事情に係る届出書（別紙様式5） | [和歌山県](https://www.pref.wakayama.lg.jp/prefg/040400/shitei_jigyosyo/syogukaizen.html) |
| 令和8年度 障害福祉サービス等 処遇改善加算 計画書（別紙様式2、大規模事業者用を含む）・実績報告書（別紙様式3）と、それぞれの記入例 | [新潟県](https://www.pref.niigata.lg.jp/sec/shougaifukushi/r8syougaisyogukaizen.html) |
| 無作為抽出の公開Excel | [data.go.jp（e-Govデータポータル）](https://data.e-gov.go.jp/) のCKAN API。一覧は `corpus/*/index.json` |
| 汎用性の検査に使った申請様式195件 | 国・都道府県・市区町村・海外の掲載ページ48か所。ページの一覧は `tests/sources.json`、個々のファイルのURLとSHA-256は取得時に `corpus/wide/index.json` に記録（`uv run python scripts/collect_forms.py` で同じものを取得） |

`tests/fixtures/kami_meisai.xlsx` は、このリポジトリのスクリプト（`scripts/make_fixtures.py`）で作った**架空の様式**で、個人情報は含みません。
計算結果はとどくが書き込み、その値はテストで手計算の値と照らしています。

## 構成

```
src/todoku/
  zipraw.py          ZIPのバイト単位の読み書き
  formula/           数式の構文解析・計算エンジン・表示形式・日付
  xlsx/workbook.py   xlsxの読み込み（セル・共有数式・配列数式・入力規則・名前・図形・メモ）
  xlsx/calc.py       再計算と全数照合
  xlsx/edit.py       バイト列の上での書き込み
  xlsx/proof.py      書き込みの独立した証明
  xlsx/example.py    記入例（Excelの答え）との照合
  xlsx/lint.py       Excelが修復なしに開くための構造の検査
  xlsx/audit.py      全て正確に読み書きできるかの検査（読み落とし・全欄への書き込み・読み戻し）
  xlsx/cf.py         条件付き書式で、いま見えている文字と色付きの欄を決める
  xlsx/window.py     AI・支援技術向けの窓（JSON・Markdown。読み順・入力欄・見出し・選択肢）
  xlsx/diagnose.py   作り手向けの診断
  report.py          診断・証明のHTML
scripts/             フィクスチャ作成・公開様式とコーパスの取得・一括検証
```
