とどくで、どう届くようにしたか

私は、自分で申請する当事者で、障害福祉の事業所の代表で、とどくの開発者です。頭につけたスイッチ 1 つで、開発・研究・経営をしています。申請する側と支える側の両方にいたから、根っこが同じ壁（行政の書類を、AI が全部正確に読み書きできない）だと見えました。そして開発者だから、その壁を越える道を自分で作れました。

行政の書類に苦労するのは、寝たきりの人だけではありません。目が見えずに読み上げで使う人、手が不自由な人、高齢の人、日本語が母語でない人、読み書きに困難のある人、仕事や介護で窓口に行けない人、毎月の書類を扱う事業所の人。誰にとっても重い作業で、その重さは、余裕のない人ほど大きくのしかかります。下の図は、その一つの例として、私の場合を測ったものです。

壁は様式の側にあり、なくすことはできません。とどくは、書類を変えずに、AI エージェントが全てを正確に読み書きできる道をつくります。どの段階も AI を使わない決まった処理で、同じ書類と同じ環境（入っている書体など）からは、必ず同じ結果が出ます。数は、この調査で段階を付けた書類のものです。

  1. 制度と様式を探す

    「私が使える制度を探して、申請書を書いて」の一言から、エージェントが制度の案内・要綱と様式を探してきます（robots.txt を守り、間をあけて取得）。当たるかどうか分からない条件は、推測で決めずに伝えます。

  2. 開いて、一字も変えずに読む

    PDF・Excel・Word・一太郎・CSV・ZIP など — の形式の書類 — 件を、元の内容を一字も変えずに読める「窓」にしました。Office も外部のライブラリも使わず、公開された仕様書から実装しています。

  3. 書く所を見つける。迷う所は「？」でエージェントに

    入力欄は、フォームの欄・入力規則・罫線・下線など、ファイルの構造から規則で見つけます。言葉の一致では決めません。規則で決められない所は、根拠を添えて「？」の印で示し、エージェントが判断します（— 件の書類）。

  4. 紙のままの壁を越える

    文字の情報がないスキャンのページ（— 件の書類）は、ページを画像にしてエージェントが見て読み、目盛りの枠で書きます。ZIP は中のファイルを開き、押印・自署は、申請する人が同意したときだけ、その人の印影の画像を置きます。

  5. 書いて、証明する

    書いたら、前と後のファイルを読み直して、変わったのが書いた所だけであることを機械で証明し、書いた値を読み戻します。部分標本 — 件で全ての欄に書き、— 件で全てを正確に読み書きできました。残りは、とどくの直す所として数えています。

  6. 対話で伝える

    私は、書類を Word や Acrobat で開きません。とどくは書類を開かずに読み書きするので、私は iPad から会話するだけです。書いた所の見出しと値・まだ空いている欄・私が決めることを、エージェントが会話でそのまま伝え、私が確かめます。

とどくを使う

とどくは、AI エージェントから使う道具（MCP サーバー）です。Claude Code にはプラグインとして入れると、どのフォルダからでも使えます。書類は手元のパソコンの中で扱い、外に送りません。

  1. 用意する

    Claude Code と、Python の道具 uv を入れます。

  2. Claude Code に入れる

    Claude Code で、次の 2 行を順に打ちます。

    /plugin marketplace add Ono-Katsuki/todoku
    /plugin install todoku@todoku

  3. 話しかける

    あとは、ふだんの言葉で頼むだけです。

    • 「住んでいる区で使える子育ての助成を探して、申請書を書いて」
    • 「この様式に、去年と同じ事業所の情報を入れて」
    • 「この Excel の計算のきまりを説明して。区分Ⅱにしたらいくら？」

  4. iPad から使う

    とどくと書類はパソコンの上に置いたまま、Claude Code の Remote Control で iPad から話しかけます。パソコンで /remote-control を実行し、iPad の Claude アプリか claude.ai/code からそのセッションにつなぎます。iPad で書類を開く必要はありません（パソコンは付けたままにします。Pro・Max・Team・Enterprise などのプランで使えます）。

ほかの MCP 対応のエージェントで使う

リポジトリ（github.com/Ono-Katsuki/todoku）を手元に置き、エージェントの MCP の設定に次を足します。

{ "mcpServers": { "todoku": { "command": "uv", "args": ["run", "--quiet", "--directory", "<リポジトリの場所>", "todoku-mcp"] } } }

方法と限界

母集団と標本

国連の加盟 193 か国の、政府のサイトにある PDF・表計算・文書・CSV の書類です。政府のサイトは、国のドメインの政府用の区分（gov.br・go.jp・lg.jp・gouv.fr・gob.mx など。Public Suffix List と各国の登録機関の規則が根拠）と、米国の .gov などの国の政府のドメイン、Wikidata にある省庁・政府の機関・自治体の公式のサイトで決めました。書類は、Common Crawl の 2026 年 10 月の収集（CC-MAIN-2026-43）の中から選びます。収集の索引を区切りごとに無作為に選び、その中の政府のサイトの書類を候補にして、国 × 形式の群の層ごとに 20 件を無作為に選びました（選ばれる確率を記録）。表計算・文書は数が少ないので、候補が 20 件に届くまで区切りを無作為に足して読みました（国ごとに 120 まで）。国は選び出さず、193 か国のすべての結果（測った・書類が収集にない・ドメインが見つからない）を地図に示しています。

分析の単位

主の単位は書類（ファイル）です。段階がファイルごとに付くためです。同じ中身の書類は 1 件に数えます。書く段階の理由は入力欄ごとにも数えます。書類の数だけでなく、字数や欄の数でも偏りを確かめます。

測ること

書類の全体を取得できたか、読む段階 S〜F、書く段階 A〜D、その理由。すべて決定的な処理です。Common Crawl は大きな書類を途中で切って保存するので、切れた書類は、そのままスコアを付けず、robots.txt が許すときだけ政府のサイトから取り直しました。10% の部分標本では、全欄に書いて、書いた所のほかはバイト一致することを証明しました。

限界

数字が表すのは「Common Crawl が集めた、政府のサイトの書類」です。Common Crawl は、リンクの多いページや HTML を先に集め、robots.txt で断られたサイトやログインの奥は集めません。Office の書類は PDF よりずっと少なく、標本の少ない国・形式は区間が広くなります。政府のドメインの一覧は、国のドメインに政府用の区分のない国（ドイツ・オランダなど）では Wikidata に頼るため、載っていない機関・自治体は入りません。切れた書類で取り直せなかったものは分母から除いているので、大きな書類が少なめに数えられます。段階の妥当性は、人の評価者 2 人による一致度（κ）で確かめる予定です。

礼儀

書類は政府のサーバーからでなく、Common Crawl の保存庫から、その記録だけを取りました（Common Crawl は集めるときに robots.txt を守っています）。保存庫への要求は一度に一つ、間をあけ、混んでいるときは待ちました。政府のサイトに行くのは、切れた書類を取り直すときだけで、robots.txt を RFC 9309 のとおりに読んで守り、同じサイトには 2 秒以上の間をあけました。ボット対策やログインは破りません。書類はスコアを付けたあとに消し、URL・SHA-256・結果だけを残しています。
