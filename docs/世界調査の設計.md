# 世界調査の設計：政府の公開書類は、AI エージェントにどこまで読めて、書けるか

2026-11-03 作成（文献はすべて、一次の記録（DOI・出版社・arXiv）で実在を確かめたもの）。

## 問い

- **RQ1 届くか**：政府が公開する書類のうち、どれだけが自動で取得できるか（robots.txt・ログイン・CAPTCHA・リンク切れ・宣言と中身の形式の食い違い）。
- **RQ2 読めるか**：取得できた書類の、読む段階（S〜F）の分布。国・形式による違い。
- **RQ3 書けるか**：書く段階（A〜D）の分布。入力欄のある書類（様式）に限った分布も出す。
- **RQ4 何が壁か**：段階を下げた理由（構造の規則で決めたもの）の分類と頻度。

読む段階と書く段階は、別々に集計し、別々に地図にする（一つの点数にまとめない）。

## 母集団と標本の枠

- **母集団**：各国の政府が、公式のオープンデータ目録に登録して公開している書類（ファイル）のうち、PDF・表計算（XLSX・XLS・ODS）・文書（DOCX・DOC・ODT・RTF）・CSV の形式のもの。調査日の時点。
- **国の母集団**：国連の加盟 193 か国（参考に香港・台湾）。国を選び出さず、全部の国に次の三つのどれかの結果を、根拠とともに記録する
  （`world/population.json`：ISO の 2 字・3 字・数字、日本語の名前、結果、目録の型、URL、理由、robots.txt の該当する行、調べた日）。
  - **届く**：政府の公式の目録に robots.txt のとおりに届き、形式の分かる登録の一覧が取れる → 標本の枠を作る。
  - **目録はあるが使えない**：robots.txt で禁止／API に鍵・登録が要る／自動の取得を拒む（403・418）／応答しない・ドメインが引けない／
    TLS の証明書を検証できない／対応する読み取り口がまだない（型の名前）。どの URL を確かめたかを記録する。
  - **公式の国の目録が見つからない**：調べた語と、確かめた政府のサイトを記録する（統計の指標のサイトだけの国は、そう書く）。
  国の公式の目録は、各国の政府のサイト・OGP の行動計画・EU の Open Data Maturity・CKAN の ecosystem などで探し、確かめた。
- **標本の枠**：目録の API が返す、書類の登録の一覧。
  - 国の目録に届く国は、その目録を使う。読み取り口：CKAN（package_search の res_format）、Socrata（Discovery API）、
    udata（/api/1/datasets）、DCAT の data.json、data.gov.sg（v2 の公開 API）。一覧を全部めくる型は、一覧を `world/catalog/` に残す。
  - EU の統合目録（data.europa.eu）は使わない：robots.txt（User-agent: *）の「Disallow: /*search?*」が検索の API
    （/api/hub/search/search?...）に当たるため。欧州の国も、国の目録に届くかどうかで決める。
  - 届かない国・目録のない国は、そのこと自体を結果として地図に示す（RQ1）。
- **robots.txt の読み方**：RFC 9309 のとおり（空行で組を閉じない・最も長く当たる行・`*` と `$`・5xx は全部禁止とみなす）。
  Python の標準の urllib.robotparser は、この三つを誤り、禁止されている目録の API を許可と答えていた（2026-11-03 に見つけて直した。
  data.gov.gr は「User-agent: *」のあとの空行、data.gov.il は「Allow: /」のあとの「Disallow: /api/」、data.overheid.nl と
  data.europa.eu は * を含む行）。その枠と、その枠で選んだ標本（ギリシャ・オランダ・イスラエルと、EU の統合目録の国）は
  `world/excluded/` に移し、集計から外した。残した標本の書類の URL も確かめ直し、いまの robots.txt で禁止に当たるもの
  （多くは robots.txt に届かない相手）を `world/excluded/robots_recheck_documents.json` に一覧にした。
- **枠の限界（論文で明記する）**：オープンデータの目録は、統計の表や報告書が多く、申請の様式は少ない。省庁の様式のページは枠に入らない。
  次の段階として、政府のホスト名の枠（Singanamalla ら 2020 の、国ごとの政府ドメインの規則と手作業の一覧）と、
  robots.txt が許す sitemap からの抽出で、様式の多い枠を足す。

## 分析の単位

- **主の単位：書類（ファイル）**。読む段階・書く段階は、ファイルごとに付くため。同じ中身（SHA-256 が同じ）は1件に数える。
  学術 PDF の大規模調査（Kumar & Wang 2024, ASSETS）も、PDF を単位にして約 2 万件を層別抽出している。
- **従の単位：入力欄**。書く段階の理由は欄ごとに数える（FormGym（Toles ら 2025）は欄を単位に評価）。
- **単位による偏りの対策**：書類の数だけでなく、ページ数・字数・欄の数で重みを付けた割合も並べて出す。
  ウェブの PDF では、3% の書類が字数の半分を持つ（Foppiano 2026, WAC）。
- **入れ子**：書類は発行者に、発行者は国に入る。国の比べは、発行者を変量効果にした混合モデル
  （Fok ら 2022, CHI のアプリの変量切片と同じ考え）で確かめる。
- **手続き（サービス）単位**：行政負担の理論（Moynihan, Herd & Harvey 2015, JPART；Herd & Moynihan 2018）では、
  負担は手続きにかかる。目録からは手続きとの対応が取れないので、この調査では書類までとし、様式の部分集合で近づける。

## 標本の取り方

- **層**：国 × 形式の群（PDF／表計算／文書／CSV）。層ごとに決まった数（250 件）を、層の中で無作為に選ぶ。
  小さな国も地図に載せられる（Singanamalla ら 2020, IMC は、ロングテールの国を落とさない枠の作り方を示した）。
- **層の中の選び方**：目録の検索の何番目かを無作為に決めて登録を1つ取り、その登録の中の、その形式の書類から1つを無作為に選ぶ（二段の抽出）。
  選ばれる確率を書類ごとに記録し、全体の推定には重み（層の書類数 ÷ 標本数 × 登録の中の書類数）を使う。
  検索が深い所まで取れない目録（EU の統合目録は 1 万件まで）は、目録の中の小さな目録（catalog）ごとに、件数に比べた確率で先に選ぶ。
- **信頼区間**：層ごとの割合には Wilson の区間（Brown, Cai & DasGupta 2001）。全体の推定は重み付きにする。
- **乱数の種**を記録し、同じ標本を作り直せるようにする。

## 測ること（決定的な処理だけ）

1. **届くか**：robots.txt・HTTP の結果・ログイン・CAPTCHA（破らず、止められたと記録）・ウェブページが返った・大きすぎる（25 MB）。
   目録で宣言された形式と、中身で見分けた形式の食い違い。
2. **段階**：とどくの `grade`（読む S〜F・書く A〜D・理由・アクセシビリティの注意）。判断が規則で決まらない所は、
   エージェントが確かめる所として数える（C に寄せる設計。PDF の評価で「判断できない」を分けて扱う Kumar, Padath & Wang 2025 と同じ考え）。
3. **入力欄の数・ページ数・字数**（重み付けのため）。
4. **道具の正しさの確かめ（部分標本）**：層別に 10% を選び、とどくの `audit`（全欄に書いて、証明・読み戻し）をかける。

## 測定の妥当性

- **道具の正しさ**：集めた様式 719 件で「全て正確に読み書きできる」こと、書き込みの証明（書いた所のほかはバイト一致）、
  記入例との照合（9,569/9,569 の数式が一致）。
- **段階の妥当性**：層別に 400 件を選び、2 人の評価者が独立に読む・書く段階を付け、Cohen の κ（Cohen 1960）と、
  段階ごとの適合率・再現率を出す。評価者の手配は今後の課題（それまでは、自動の段階と、別の道具（PDF は veraPDF）との食い違いを出す）。
  自動の検査だけに頼る危うさ（Vigo, Brown & Conway 2013, W4A）を明記する。

## 倫理

- robots.txt を RFC 9309 のとおりに守り（目録の API も）、同じ相手には 2 秒以上（Crawl-delay があればその長さ）の間をあける。名乗る User-Agent を付ける（Thelwall & Stuart 2006）。
- CAPTCHA・ボット対策は破らない。ログインの要るものには入らない。
- 取得した書類は、段階を付けたら消す（確かめ直し用の部分標本だけを手元に残し、公開しない）。公開するのは URL・SHA-256・結果だけ。
- 論文には倫理の節を置く（Partridge & Allman 2016）。
